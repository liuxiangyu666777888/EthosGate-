# EthosGate · 善治 项目文档

开源仓库：https://github.com/liuxiangyu666777888/EthosGate-

## 一、项目背景

大语言模型已经进入教育、办公、客服和内容生产等真实业务场景。很多团队在模型上线前会测试准确率、延迟、成本和稳定性，但伦理评估仍常停留在会议讨论或表格打分上。这样的问题是：判断过程不够透明，证据不易复核，模型真实输出和最终上线结论之间缺少清晰联系。尤其在教育、医疗、金融、政务等高影响领域，“模型看起来能用”不能直接等同于“模型适合上线”。

EthosGate · 善治的主题是“面向 LLM 部署决策的多方参与评估工具”。系统目标是在模型上线前帮助团队走过预测、反思、包容、响应四个维度，形成可复核的伦理评估报告。它不是自动伦理打分器，也不把 LLM 当成最终裁判，而是一个治理工作台：让项目负责人、技术评估人员、伦理审查人员和外部参与者围绕同一套证据讨论，并留下审计记录。

项目的理论基础来自负责任创新框架。预测要求团队提前识别潜在危害；反思要求团队检查价值预设和设计盲点；包容强调纳入受影响群体；响应要求模型上线后仍能根据反馈、事故和监控结果调整。本系统在四个维度之外加入“被部署模型实测”，要求用户连接真实模型接口，运行红队测试用例，把模型实际输出纳入证据链。

## 二、系统需求设计

系统按内部试点版设计。主要角色包括项目负责人、技术评估人员、伦理审查人员和外部审阅者。项目负责人创建项目，填写部署边界和责任主体；技术评估人员配置被测模型接口，运行测试套件并补充风险证据；伦理审查人员复核 AI 草稿、模型实测结果和门禁结论；外部审阅者可参与证据审阅或查看报告。

系统功能需求包括六部分。第一是项目设置，记录模型名称、版本、部署领域、目标用户、人工复核、申诉渠道和事故响应机制。第二是四维评估流程，提供预测、反思、包容、响应模块，支持填写证据类型、证据链接、理由、置信度、评估人和复核人。第三是模型实测，支持配置 OpenAI 兼容 Base URL、模型名、鉴权 Header 和运行时 API Key，并执行教育辅导 LLM 红队测试套件。API Key 不明文保存，系统只保留脱敏提示。第四是证据中心，统一展示风险问卷、参与记录、模型实测和 LLM 辅助审计。第五是伦理门禁，根据证据状态输出四类结论：READY、READY_WITH_CONDITIONS、NEEDS_REVIEW、BLOCKED。第六是报告导出，生成 Markdown 和 HTML 报告，并区分正式证据、待复核附件和 AI 草稿。

非功能需求包括可运行性、安全性和可维护性。系统支持 SQLite 本地回退，也提供 PostgreSQL Docker Compose 配置。后端提供 JWT 登录和角色权限控制。LLM 辅助功能在没有 OPENAI_API_KEY 时返回明确错误。生产或准生产环境需要设置强 JWT_SECRET，并关闭默认管理员密码。前端登录后直接进入工作台，展示项目状态、门禁缺口、风险汇总和下一步行动。

## 三、详细设计

系统采用前后端分离结构。后端使用 FastAPI、SQLAlchemy 2、Pydantic Settings 和 Alembic；前端使用 Vite、React、TypeScript、ECharts 和 lucide-react。数据库默认读取 DATABASE_URL，没有配置时回退到 backend/data/app.db。根目录提供 package.json，可并发启动前后端。

后端核心实体包括 User、Project、ModuleResult、RiskResponse、StakeholderGroup、EngagementRecord、ComplianceMapping、LLMAuditRecord、GateDecision、ModelConnection、ModelTestSuite、ModelTestCase、ModelTestRun、ModelTestResult 和 EvidenceItem。Project 保存项目基本信息、部署上下文和治理边界。RiskResponse 保存风险条目，并按严重性、可能性、暴露规模、脆弱性权重和缓解可信度计算剩余风险。StakeholderGroup 和 EngagementRecord 记录受影响群体和参与闭环。LLMAuditRecord 记录 OpenAI Responses API 辅助生成的草稿及人工状态。

模型实测模块是本项目区别于普通问卷系统的关键部分。系统内置“教育辅导 LLM 伦理红队测试”套件，覆盖偏见、未成年人隐私、安全绕过、钓鱼滥用、过度拒答、申诉、幻觉、提示注入和教师复核边界。用户配置被测模型后，后端向该模型发送测试 prompt，并保存输出、错误、规则信号、严重度和预期安全行为。规则层只做初筛。LLM judge 可以生成辅助评审草稿，但草稿默认是 draft。只有伦理审查人员将某条结果标记为 accepted 或 revised 后，它才会进入正式证据链。

伦理门禁逻辑体现“人工主导、证据驱动”。若存在高严重性且无缓解责任人的风险，或高影响领域缺少人工复核、申诉、事故响应机制，系统返回 BLOCKED。若核心证据低置信度、弱势高影响群体没有参与计划、LLM 输出未人工确认、模型实测尚未执行或仍有草稿，系统返回 NEEDS_REVIEW。若存在中高风险但缓解措施和负责人已记录，系统返回 READY_WITH_CONDITIONS。只有核心模块完成、无未处理高风险且模型实测结果已经复核时，系统才返回 READY。

前端设计为治理工作台。左侧是项目列表和门禁快照，主区域包括总览、项目设置、预测、模型实测、证据中心、反思、包容、响应、法规、LLM 审计和报告页面。模型实测页支持保存连接、选择测试套件、运行测试、查看端点指纹和逐条复核。证据中心把正式证据和待复核材料分开显示。报告页会先触发门禁评估，再展示 Markdown 报告，并提供 HTML 报告入口。

## 四、系统使用说明

后端运行方式：

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m uvicorn app.main:app --reload --port 8000
```

如需使用 LLM 辅助评审，需要设置 OPENAI_API_KEY。没有该环境变量时，普通评估、模型实测和报告仍可使用。

前端运行方式：

```bash
cd frontend
npm install
npm run dev
```

也可以在项目根目录执行 `npm run dev` 同时启动前后端。启动后访问 `http://localhost:5173/`，后端接口文档位于 `http://localhost:8000/docs`。默认账号为 `admin@example.com`，密码为 `admin123456`。如使用 PostgreSQL，可运行 `docker compose up -d postgres`，再设置 `DATABASE_URL=postgresql+psycopg://ethics:ethics@localhost:5432/ethics_dashboard`。

典型流程是：登录并打开种子项目或新建项目；在项目设置中填写部署边界、人工复核、申诉和事故响应；进入预测、反思、包容、响应模块补充风险、价值预设、参与闭环和监控计划；进入模型实测页，配置被测模型 Base URL、模型名和运行时 API Key，选择测试套件并运行；逐条复核模型输出，把可信结果标记为 accepted，把确认存在问题的结果标记为 revised；最后进入证据中心检查材料，并在报告页生成门禁结论和伦理评估报告。

当前实现适合课程展示和内部试点。若后续面向公开 SaaS，还需补充多租户隔离、企业 SSO、密钥托管、异步测试队列、PDF 导出、操作监控和更完整的权限审计。
